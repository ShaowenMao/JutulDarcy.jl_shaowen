# Step62 `sandpc_ycap50_v1` three-case workflow

This is an opt-in workflow for canonical seven-case manifest tasks 5–7:

| Task | Case key |
|---:|---|
| 5 | `s03_c001_case04` |
| 6 | `s03_c012_case08` |
| 7 | `s04_c024_case03` |

It does not alter or reuse the accepted `gom_step62_production_*` result
directories. The immutable campaign ID must contain both `sandpc` and
`ycap50`, and every stage uses the versioned
`gom_step62_sandpc_ycap50_*` result prefix.

## Locked physics contract

- Step62, 87 slices, 2,165,082 cells.
- Eight shared saturation regions:
  host LM2, seal, three non-PREDICT bands, Al/Ar sand, host MM–UM,
  and host Younger.
- 522 sample-specific PREDICT regions.
- 530 drainage regions and 1,060 drainage/imbibition SGOF tables.
- Host and non-PREDICT Pc use the 30-degree sand reference.
- Host Pc is Leverett-scaled with vertical permeability.
- Non-PREDICT Pc is Leverett-scaled with local fault `kzz`.
- Non-PREDICT Younger local permeability is `[50, 500, 500]` mD.
- Kr curves and their native saturation support are retained.
- The Pc plateau applies only to the 522 explicit PREDICT tables.
- Hysteresis is active.
- JutulDarcy computes transmissibilities; MRST `T` is omitted.
- `PRODUCTION_QOI_MODE=required`.

The preflight validates the complete Pc curves on the native drainage and
imbibition saturation nodes, the three eigenvalues of every modified Younger
tensor, all region/table counts, QoI masks/interfaces, positive-definite
permeability, and positive Jutul transmissibility.

## Scheduler resources

Measured prior runtimes for tasks 5–7 were approximately 14 h 41 min
(including task-5 continuation after a 12 h timeout), 7 h 31 min, and
5 h 27 min. The full-stage default is therefore 24 hours:

```bash
export GOM_SANDPC_FULL_WALLTIME=1-00:00:00
```

The `mit_amf_advanced_cpu` QoS was checked with `sbatch --test-only`; it
accepts this limit on `mit_normal`. The limit remains configurable. Full and
smoke jobs use eight CPUs and 18 GiB; observed full-job MaxRSS was
approximately 12.3–13.0 GiB. Other stage limits remain:

- campaign check: 30 minutes, 2 GiB;
- preflight: 2 hours, 24 GiB;
- smoke: 4 hours, 18 GiB;
- VTU: 3 hours, 24 GiB;
- archive: 8 hours, 4 GiB.

All three tasks run concurrently; there is no array concurrency cap.

## Submission

The input package remains a seven-case immutable manifest so task identity is
never renumbered. It must be generated by the dedicated, opt-in preparation
job; the accepted default-physics preparation job must not be reused:

```bash
export MRST_ROOT=/path/to/mrst
export MRST_PREP_REPO=/path/to/pinned/mrst_predict_sim
export JUTULDARCY_COMBINED_REPO=/path/to/pinned/JutulDarcy.jl
export GOM_SANDPC_SOURCE_MANIFEST=/absolute/path/to/source_manifest.csv
export GOM_SANDPC_DERIVED_DIR=/new/immutable/input/directory
export GOM_SANDPC_CAMPAIGN_DIR=/new/immutable/campaign/directory
export GOM_SANDPC_CAMPAIGN_ID=step62_new3_sandpc_ycap50_v1
export GOM_PRODUCTION_ARCHIVE_ROOT=/orcd/data/juanes/001/shaowen/gom_grid
sbatch \
  "$JUTULDARCY_COMBINED_REPO/scripts/engaging/gom_step62_sandpc_ycap50_input_prepare.sbatch"
```

Preparation passes `PhysicsProfile='sandpc_ycap50_v1'` explicitly. It creates
and validates the versioned fixed-SGR asset
`physics_assets/faultPermSGR_Gupper87lyr_predictMesh_youngerkxx50_v1.mat`,
includes that asset in the immutable checksums/provenance, and refuses
pre-existing derived or campaign directories.

After preparation passes, only tasks 5–7 are submitted:

```bash
export JUTULDARCY_COMBINED_REPO=/path/to/pinned/JutulDarcy.jl
export GOM_PRODUCTION_MANIFEST=/absolute/path/to/campaign.toml
export GOM_GRID_ROOT="$HOME/orcd/scratch/gom_grid"
bash \
  "$JUTULDARCY_COMBINED_REPO/scripts/engaging/gom_step62_sandpc_ycap50_submit.sh"
```

The DAG is:

1. immutable campaign/checksum validation;
2. setup-only preflight for tasks 5–7;
3. three-step restart/QoI smoke test;
4. complete 1,000-year run;
5. compact initial/50-year/1,000-year VTUs;
6. checksum-verified atomic archive promotion.

The full stage explicitly starts with `RESTART_RUN=false` in a new result
directory and refuses any pre-existing case directory. It therefore cannot
resume checkpoints from the accepted campaign.

## Temporal QoI validation

The final validator requires:

- exactly 210 production and QoI step bundles;
- exactly 210 global rows, 14,490 regional rows, and 40,530 interface rows;
- exactly 69 region IDs and 193 interface IDs at every report time;
- exact case key and campaign-manifest SHA-256 on every temporal row;
- time vectors identical to `report_steps.tsv`;
- matching region/interface manifest hashes in the completion marker;
- a complete case summary and empty staged-QoI directory;
- the accepted retained hysteresis states at report steps 78 and 210.

The temporal schema and spatial mask definitions are unchanged. Values are
expected to change because the Pc and Younger permeability physics changed.
